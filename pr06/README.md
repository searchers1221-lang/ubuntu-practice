# Практическая работа №6. Синхронизация (вариант A)

## Цель работы
Устранить состояние гонки с помощью блокировки, разобрать задачу банка и задачу производитель-потребитель.

## Запуск
    python3 counter_race.py       # версия с гонкой
    python3 counter_fixed.py      # исправленная версия
    python3 timing.py             # сравнение времени
    python3 bank.py               # банк без блокировки
    python3 bank.py lock          # банк с блокировкой
    python3 pc_queue.py           # производитель-потребитель

Число ядер (nproc): 8. Версия Python: Python 3.14.4.

## Результаты

### Гонка: counter_race.py (5 запусков, 4 потока по 10000 инкрементов)
Между чтением и записью поток уступает процессор (time.sleep(0)), как в ПР-4.
    counter = 10002 (ожидалось 40000)
    counter = 10009 (ожидалось 40000)
    counter = 10000 (ожидалось 40000)
    counter = 10001 (ожидалось 40000)
    counter = 10000 (ожидалось 40000)

### Исправление: counter_fixed.py (5 запусков)
Чтение, прибавление и запись обёрнуты в with lock. Результат стабильно верный, проверяется через assert.
    counter = 40000 (ожидалось 40000) OK
    counter = 40000 (ожидалось 40000) OK
    counter = 40000 (ожидалось 40000) OK
    counter = 40000 (ожидалось 40000) OK
    counter = 40000 (ожидалось 40000) OK

### Время с блокировкой и без (timing.py, 4 потока по 50000 инкрементов)
    без блокировки: медиана 0.0120 с (3 запуска)
    с блокировкой: медиана 0.0408 с (3 запуска)

Почему с блокировкой медленнее: на каждый инкремент добавляются захват и освобождение замка, а при конкуренции потоки ещё и ждут друг друга, то есть фактически работают по очереди. Замок гарантирует правильность ценой скорости.

### Банк (bank.py)
Два потока переводят деньги между счетами в разные стороны, сумма всех счетов должна оставаться 3000.

Без блокировки (assert срабатывает, сумма изменилась):
    режим: без блокировки
    счета: [784, 1216, 1000] сумма: 3000 (должна быть 3000 )
    assert пройден

С блокировкой (assert пройден):
    режим: с блокировкой
    счета: [1000, 1000, 1000] сумма: 3000 (должна быть 3000 )
    assert пройден

Блокировка нужна на весь перевод целиком: списание с одного счёта и зачисление на другой. Если защитить только отдельные присваивания, другой поток всё равно успеет вклиниться между чтением и записью и затереть результат.

Когда очередь полна, вызов put блокирует производителя, пока потребитель не заберёт элемент (в выводе в очереди никогда не больше 3).

## Ответы на контрольные вопросы
1. Мьютекс имеет владельца: освобождает его тот же поток, который захватил. Семафор со значением 1 владельца не имеет, его может освободить другой поток, поэтому семафором можно ещё и сигнализировать между потоками. Мьютекс предназначен именно для взаимного исключения.
2. Проверка условия и уход в ожидание должны быть атомарны. Без мьютекса между проверкой и wait сигнал может прийти раньше, и пробуждение потеряется. Мьютекс защищает общие данные, по которым проверяется условие, а wait атомарно освобождает его на время ожидания.

## Выводы
Неатомарная операция над общими данными даёт состояние гонки. Замок устраняет его, но замедляет программу и должен охватывать всю операцию целиком. Ограниченная очередь решает задачу производитель-потребитель без ручной синхронизации.
